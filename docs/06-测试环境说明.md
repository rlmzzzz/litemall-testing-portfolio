## 零、先搞懂「9527 / 8080 / 3307」是什么

### 一句话类比

> **IP 地址 = 小区地址，端口 = 房间号。**
> 快递员知道小区在哪（IP），还得知道送进哪一户（端口）。

`localhost` 就是"你自己这台电脑"的固定叫法（等同于 `127.0.0.1`）。
所以 `localhost:9527` 的意思是：**访问你这台电脑的第 9527 号服务**。

### 冒号前后分别是什么

```
http://localhost:9527
        └──┬──┘ └─┬─┘
         地址    端口
```

### 这三个端口各是谁

| 端口 | 谁在用 | 打开/访问方式 | 里面实际是谁 |
|---|---|---|---|
| **9527** | 前端页面 | 浏览器地址栏 | Nginx 容器（容器内部端口 80） |
| **8080** | 接口 | Postman / JMeter / 浏览器粘 URL | Java 后端容器（容器内部也是 8080） |
| **3307** | 数据库 | 命令行 / 图形化工具 | MySQL 容器（容器内部是 **3306**） |

> **注意左边和右边不一样**：`docker ps` 里看到的 `0.0.0.0:9527->80/tcp`，
> 意思是"外面的 9527 号门，通向容器里面的 80 号"。这是 Docker 的**端口映射**。

### 为什么要改端口（这条面试能讲）

**一个端口同一时间只能被一个程序占用。**

litemall 的 MySQL 本来想用 3306（MySQL 的默认端口），但你电脑上已经有一个 MySQL 8.0 占着 3306 了，
两个抢同一个门牌号就会冲突，所以改成 **3307** 避开。同理，你本机禅道有时会占 3307，
这时 litemall 就抢不到——所以我们查数据改用 `docker exec` 直接从容器内部连，压根不走门口，也就不会被抢。

### 常见疑问

| 疑问 | 解释 |
|---|---|
| 端口是自己编的吗？ | 不是。9527 是 litemall 前端自己定的，8080 是 Java 后端默认的，3306 是 MySQL 默认的。我们只是把冲突的那个改成 3307 |
| 能改成别的吗？ | 能，在 `docker-compose.yml` 里改 `ports:` 那一行，改完 restart 容器 |
| 忘记了怎么办？ | `docker ps` 看 PORTS 那一列，或 `docker port 容器名` |

## 附：docker run 是什么意思

### 一句话

`docker run` = **拿一个镜像，造一个容器，并把它启动起来。**

它等于把三件事合成一条命令：`pull`（拉镜像）→ `create`（建容器）→ `start`（启动）。

### 镜像 vs 容器（最容易混的一对）

| | 镜像 Image | 容器 Container |
|---|---|---|
| 是什么 | 只读的**模板** | 跑起来的**实例** |
| 类比 | 类 / 安装包 | new 出来的对象 / 装好的软件 |
| 能不能改 | 不能（只读） | 能（可读可写） |
| 数量关系 | 一个镜像 → 可以起**多个**容器 | |
| 命令看它 | `docker images` | `docker ps`（加 `-a` 看已停止的） |

```powershell
docker rm demo-nginx     # 删容器，镜像还在
docker rmi nginx:alpine  # 删镜像
```

### 常用参数对照

| 参数 | 作用 | 本项目的实际例子 |
|---|---|---|
| `-d` | 后台运行，不占着终端 | 三个容器都是 `-d` 起的 |
| `-p 外:内` | 端口映射 | `-p 8081:80`：外面 8081 通向容器 80 |
| `--name` | 给容器起名字 | `--name demo-nginx` |
| `-e` | 传环境变量 | MySQL 用 `-e MYSQL_ROOT_PASSWORD=xxx` |
| `-v` | 挂载目录（数据持久化） | 本项目挂载了 storage / logs |
| `--rm` | 停了就自动删除 | 临时验证时用 |

> 这些参数本项目都写在 `docker-compose.yml` 里了，所以你不用一个个敲。

### 实机验证过的一段（2026-09-18）

```powershell
docker run -d -p 8081:80 --name demo-nginx nginx:alpine
```

返回一长串容器 ID，`docker ps` 里多出 `demo-nginx`，浏览器访问 `http://localhost:8081` 返回
**HTTP 200 / 标题 Welcome to nginx!** —— 一条命令就有了一个全新的网站。

另外跑 `docker run --rm hello-world` 时，Docker 官方输出里自己说明了它做了什么（翻译）：

> 1. Docker 客户端联系守护进程
> 2. 守护进程从 Docker Hub 拉取 `hello-world` 镜像
> 3. 守护进程用这个镜像创建了一个新容器，并运行它
> 4. 守护进程把输出流传回你的终端

**这四步就是 `docker run` 的全部。**

### run 和 compose up 的区别（面试常问）

| | `docker run` | `docker compose up` |
|---|---|---|
| 一次起几个 | 一个 | yml 里写几个起几个 |
| 参数 | 全敲在命令行，长了难维护 | 写进 yml，可复用可版本管理 |
| 依赖关系 | 不管（谁先起要你自己排） | 支持 `depends_on` |
| 适合 | 临时验证单个容器 | 多服务项目 |

> 本项目是三个服务 + 有依赖顺序，所以用 **compose**，不是一条条 `docker run`。

## 三、数据库连接

> ⚠️ **2026-09-18 更正**：宿主 `3307` 端口实际被**本机禅道的 MySQL** 占用（里面是 `zentao` 库），
> litemall 容器的 3307 映射抢不到这个端口。**所以不要用 Navicat 连 3307 找 litemall，会连到禅道库去。**

**推荐方式：直接进容器查（不受端口冲突影响）**

```powershell
docker exec -it mysql mysql -uroot -plitemall123456 litemall
```

或者在宿主机上直接执行单条 SQL（无需进入交互界面）：

```powershell
docker exec mysql mysql -uroot -plitemall123456 litemall -N -B -e "SELECT id,name,retail_price FROM litemall_goods LIMIT 10;"
```

| 项 | 值 |
|---|---|
| 库名 | `litemall` |
| 账号 | `root` 或 `litemall` |
| 密码 | `litemall123456` |
| 图形化工具端口 | 暂不可用（3307 被禅道占用）。要用 Navicat 的话需改 compose 映射为 `3308:3306` |

**本机 3307 上的另一个数据库（禅道）**：`root` / `123456`，库名 `zentao` —— 别和 litemall 搞混。

## 六、日常操作命令

在项目 docker 目录下操作（`cd D:\litemall\litemall-master\docker`）：

```powershell
docker compose up -d          # 一次启动全部三个服务
docker compose down           # 停止并移除容器
docker compose ps             # 查看状态
docker compose restart        # 重启全部
docker restart litemall       # 只重启后端
docker logs -f litemall       # 看后端实时日志（排错、查报错堆栈用）
docker exec -it mysql mysql -uroot -plitemall123456 litemall   # 进数据库
```

**开机后怎么恢复测试环境：**
双击桌面 Docker Desktop → 等左下角变绿 → 进 docker 目录跑 `docker compose up -d` → 打开 http://localhost:9527

> 注意：改了 `litemall-admin/dist` 之后要重新复制到 `docker/admin-dist/`，nginx 才吃得到新页面。

**数据弄乱了要重置：**

```powershell
docker compose down
docker volume prune           # 或手动删 D:\litemall\litemall-master\docker\db\data 里的内容
docker compose up -d
```

（数据库会按 init-sql 里的脚本重新初始化）

## 七、环境搭建踩坑记录（面试素材）

这一节能直接讲给面试官听，"你怎么搭的测试环境、遇到了什么问题" 就有真实内容了。

1. **Docker Desktop 连不上 Server** —— WSL 未安装，用 `wsl --install` 装完后重启解决。
2. **国内拉不到镜像** —— 配了 registry-mirrors（轩辕、毫秒、DaoCloud 等），之前常用的网易/百度源 2026 年已失效。
3. **C 盘只剩 9GB** —— Docker 默认数据盘在 C 盘，改 Settings → Resources → Disk image location 到 `D:\DockerData`。
4. **`docker-compose up` 必然失败** —— 开源仓库只给源码，`docker/litemall/Dockerfile` 里的 `COPY litemall.jar` 找不到文件，必须先 Maven 编译打包。
5. **Dockerfile 基础镜像已下架** —— 原写的是 `openjdk:8-jre`，Docker Hub 已移除，改成 `eclipse-temurin:8-jre`。
6. **MySQL 端口冲突** —— 本机已有 MySQL 8.0 占用 3306，把容器映射到宿主的 3307。
7. **后端比 MySQL 先启动会连库失败** —— 报 `Server shutdown in progress`，只需等 MySQL 就绪后 `docker restart litemall`。
8. **Node 22 编译 Vue2 老项目** —— webpack 4 用的 md4 哈希在新 OpenSSL 下不支持，需要加 `NODE_OPTIONS=--openssl-legacy-provider` 才能编译通过。
9. **3307 端口被禅道抢占** —— 本机禅道（zbox 一键包，装于 `D:\app\ZenTao`）自带 MySQL 占用了 3307，导致 litemall 容器的 3307 映射连不上，用 Navicat 连 3307 会连到 `zentao` 库。改用 `docker exec mysql mysql ...` 进容器查，不受影响。
10. **电脑重启后 Docker 不自启** —— 服务会全部消失、浏览器报 `ERR_CONNECTION_REFUSED`。解法：打开 Docker Desktop 等引擎就绪（约 20 秒），容器会自动拉起。建议在 Settings → General 勾选 Start Docker Desktop when you sign in。

## 九、本机禅道（提 Bug 用）

zbox 一键安装包，装在 `D:\app\ZenTao`，版本 22.5。

**登录要过两层**（这是最容易懵的地方）：

| 层次 | 说明 | 账号 / 密码 |
|---|---|---|
| 第 1 层：Apache Basic 认证 | 浏览器弹出的**原生小窗口**（不是禅道页面） | `zentao` / `123456` |
| 第 2 层：禅道登录页 | 过完第 1 层才看得到 | `admin` / `123456`（2026-09-18 已重置） |

> 第 1 层的配置在 `D:\app\ZenTao\app\zentao\www\.ztaccess`，
> 密码文件 `D:\app\ZenTao\bin\apache\auth\.htaccess`（可用 `bin\apache\bin\htpasswd.exe` 改）。

**改 admin 密码**（禅道密码存的是明文 md5）：

```sql
UPDATE zentao.zt_user SET password = MD5('你要的密码') WHERE account = 'admin';
```

连接：`mysql -h127.0.0.1 -P3307 -uroot -p123456`
9. **前后端分离会有跨域问题** —— 后端没有全局跨域配置，所以不用 `npm run dev`，改成 build 静态页面后用 Nginx 反向代理 `/admin` 到后端，页面和接口同源（都是 9527），跨域问题直接消失。
