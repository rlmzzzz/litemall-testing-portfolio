## 1. 项目概述

litemall 是一个轻量级开源电商系统，包含**用户端商城（H5）**、**后台管理系统**与**接口服务**三部分。本轮测试对其核心业务链路做完整功能、接口、性能与安全验证，目标是通过一个完整项目走通软件测试全流程，产出可追溯的测试资产。

- 前端商城：`http://localhost:<端口>`（端口见 docker-compose.yml 映射）
- 后台管理：`http://localhost:<端口>/admin`
- 数据库：MySQL，库名 `litemall`

## 2. 测试范围

### 2.1 在测模块

| 序号 | 模块 | 测试重点 |
|---|---|---|
| M1 | 注册登录 | 账号密码校验、验证码、登录态、退出 |
| M2 | 商品与搜索 | 列表分页、搜索、规格切换、上下架 |
| M3 | 购物车 | 加购、数量修改、删除、金额计算、持久化 |
| M4 | 下单结算 | 地址、优惠券、运费、库存、金额精度、重复提交 |
| M5 | 支付 | 模拟支付、超时关闭、异常支付 |
| M6 | 订单管理 | 状态流转、列表筛选、取消、确认收货 |
| M7 | 售后退款 | 退款申请、金额与库存回滚 |
| M8 | 后台管理 | 商品/订单/用户管理、发货、权限 |

### 2.2 明确不测（写清楚反而显得专业）

- 微信小程序端（无开发者工具环境）
- 真实第三方支付回调（微信/支付宝沙箱不可得）
- 源码级单元测试与白盒覆盖
- 短信验证码真实下发

## 4. 测试策略

| 轮次 | 目标 | 范围 | 通过标准 |
|---|---|---|---|
| 冒烟测试 | 确认主流程可通，避免无效投入 | 登录、浏览、加购、下单、支付 5 条 P0 | 全部通过 |
| 第一轮（全量） | 全面发现缺陷 | 全部 76 条用例 | 执行率 100% |
| 第二轮（回归+探索） | 验证修复 + 补充异常场景 | 失败用例 + 安全/并发/兼容专项 | P0/P1 缺陷清零 |

| 类型 | 内容 | 工具 |

## 6. 用例规范

- 编号规则：`TC-<模块>-<三位序号>`，如 `TC-ORDER-001`
- 必备要素：用例编号、所属模块、用例标题、前置条件、操作步骤、测试数据、预期结果、优先级、用例类型、设计方法
- 设计方法覆盖：等价类划分、边界值、场景法、判定表、因果图、正交试验、错误推测
- 优先级定义：

| 级别 | 含义 |
|---|---|
| P0 | 核心主流程，失败则系统不可用 |
| P1 | 重要功能与主要异常分支 |
| P2 | 边界值、次要功能 |
| P3 | 体验、建议类 |

## 7. 缺陷规范

| 严重程度 | 定义 |
|---|---|
| 致命 | 系统崩溃、数据错乱、资金/库存错误、严重安全漏洞 |
| 严重 | 主流程某分支不可用、结果与预期明显不符 |
| 一般 | 次要功能异常，有变通办法 |
| 轻微 | UI、文案、样式问题 |
| 建议 | 优化建议 |

**标题写法**：`【模块】+ 现象 + 条件`，例如 `【下单结算】50 并发下单导致库存扣减为负数`

**必附内容**：前置条件、详细复现步骤（1、2、3）、预期结果、实际结果、截图/日志/抓包证据、发生环境

**生命周期**：新建 → 激活 → 已解决 → 已关闭（或 已拒绝）

## 9. 准入准出标准

**准入**：环境可访问、冒烟 5 条 P0 用例全部通过、测试数据已准备

**准出**：
- 用例执行率 100%
- P0、P1 缺陷全部关闭
- P2 及以下遗留缺陷 ≤ 3 个且已评估风险
- 核心接口通过率 100%
- 压测结论已给出

## 10. 风险与应对

| 风险 | 应对 |
|---|---|
| Docker 部署失败 | 改用本地源码启动（JDK + Maven + Node）；或换用 RuoYi-Vue |
| 挖不出真正的 Bug | 重点挖并发超卖、越权、金额精度、特殊字符、状态机跳变（见缺陷清单示例） |
| 时间不够 | 保住「功能 + 用例 + 缺陷 + 接口」四件套，性能与自动化可简化 |
