### 为什么废弃单集合方案

多账号写在一个集合里跑 Newman 时，**所有带 token 的用例全部返回 errno=506**，但 Postman 里手工点又正常。

根因：登录接口下发 `Set-Cookie: JSESSIONID`，Newman 的 cookie jar 会自动保存并在后续请求携带；而**后端 cookie 鉴权优先级高于 token 请求头**。集合里依次登录 admin123 → mall123 → promotion123，cookie 身份被最后一个低权限账号覆盖，于是后面带 admin123 的 token 也按低权限鉴权 → 506。

**解决：按账号拆成 5 个集合分别跑。** 详见 `12-接口测试报告.md` 第一节。

## 一、为什么做接口测试（这一步的价值）

功能测试是**从界面验证**，接口测试是**绕过界面直接验证逻辑**。它有三个界面测试做不到的地方：

| 界面测试做不到 | 接口测试能做到 |
|---|---|
| 越权要登录两个账号切来切去 | 直接换 token 请求，一次验证 |
| 异常参数界面可能根本输不进去 | 可以传负数、超长、非法类型，看后端拦不拦 |
| 只能看页面显示 | 能看原始响应体、错误码、响应时间 |

**而且这次实测证明了一件重要的事**：价格负数 Bug 在**界面和接口两条路径都能复现**——说明问题在后端校验，不在前端。这个判断只有接口测试能做出来。

## 三、怎么用（3 步）

**第 1 步：导入集合**
Postman → 左上角 **Import** → 把 `litemall.postman_collection.json` 拖进去 → Import。
（环境变量文件可选导入，不导也能跑，集合变量里已经预置了 `baseUrl`）

**第 2 步：先跑 01 目录**
点开 `01-登录与鉴权` → 逐个 Send。登录成功后 token 会**自动写入集合变量**，后面所有请求不用手动填。

> 原理写在 1.1 的 Tests 里：
> ```js
> pm.collectionVariables.set("adminToken", j.data.token);
> ```
> 这就是**接口关联**——把上游响应里的数据取出来，给下游请求用。面试必考点。

**第 3 步：批量跑**
右侧 **Runner**（或集合名旁 **Run**）→ 选中整个集合 → **Run litemall 接口测试集合** → 看断言通过情况。

## 四、断言是怎么设计的（面试可讲）

每条请求都写了 3~5 个断言，**不是只判断"通不通"**：

| 断言类型 | 例子 | 为什么要有 |
|---|---|---|
| HTTP 状态码 | `pm.response.to.have.status(200)` | 最基础 |
| **业务错误码** | `pm.expect(json.errno).to.eql(0)` | HTTP 200 不代表业务成功，本项目所有错误都返回 200 + errno |
| **响应时间** | `pm.expect(pm.response.responseTime).to.be.below(2000)` | 性能门槛 |
| **业务字段** | `列表非空`、`total > 0`、`名称包含关键字` | 防止"返回空数据也算通过" |
| **异常码精确匹配** | 未登录=501、越权=506、参数错=402 | 区分不同的失败原因 |

**这套断言里最值得讲的一句**：

> 这个项目所有响应 HTTP 都是 200，真正的成功与否要看响应体里的 `errno`。所以我的断言不能只判断状态码，必须解析 JSON 校验业务错误码。

## 五、接口层的新发现（2 个）

### 🐛 Bug-6【一般】查询不存在的商品 ID 返回「系统内部错误」

| 请求 | 期望 | 实际 |
|---|---|---|
| `/admin/goods/detail?id=99999999` | 提示"商品不存在" | `errno:502 系统内部错误` |
| `/admin/goods/detail?id=0` | 同上 | `502` |
| `/admin/goods/detail?id=-1` | 同上 | `502` |
| `/admin/goods/detail?id=abc` | 参数错误 | `402 参数值不对` ✅ 正确 |

**判断依据**：`id=abc` 能正确返回 402（说明参数校验做了），但 id 合法却不存在时返回 502（说明**业务异常没有 catch**）。502 是"系统内部错误"，对用户来说是莫名其妙的提示，属于异常处理不当。

### ✅ Bug-5 接口层复现（与界面路径相互印证）

```
POST /admin/goods/create  专柜价 -1  →  errno: 0「成功」，落库 counter_price = -1.00
```

界面路径（你提的那个禅道 Bug）和接口路径**都能复现**，结论更硬：**这是后端校验缺失，不是前端漏判**。

### 📝 观察项：分页越界（需求未明确，不建议当 Bug 提）

`page=9999&limit=5` → 返回 `errno:0`，4 条数据。
原因是 MyBatis PageHelper 的"合理化"配置会把超大页号纠正到最后一页（249 条 / 每页 5 → 最后一页 4 条）。
**这是框架的默认行为，不是缺陷**，写进观察记录即可，硬提容易被驳回。

## 六、用 Newman 出报告（写进简历的那一步）

Newman 是 Postman 的命令行版，能在命令行批量跑集合并生成 HTML 报告。

```powershell
newman run "C:\Users\李玉亭\WorkBuddy\2026-09-15-16-30-32\litemall-测试实战\接口测试\litemall.postman_collection.json" -r htmlextra --reporter-htmlextra-export "接口测试报告.html"

**报告里要看的三件事**：断言通过率、失败的是哪条（失败不等于坏事，标了 [缺陷] 的就是故意让它暴露）、响应时间分布。

> 若提示 `newman 不是内部命令`，先装：`npm install -g newman`（需要 Node.js，你本机已有）。

## 七、面试会问的接口题（答案要点）

**Q1：接口测试测什么？**
状态码、响应体字段、业务错误码、异常参数、权限控制、响应时间、数据一致性（接口返回 vs 数据库）。

**Q2：token 关联怎么做？**
登录接口响应里取 `data.token`，用 `pm.collectionVariables.set()` 存进变量，后续请求在 header 里用 `{{adminToken}}` 引用。

**Q3：HTTP 200 就代表成功吗？**
不一定。本项目所有业务错误也返回 200，靠响应体 `errno` 区分（501 未登录 / 506 无权限 / 402 参数错 / 502 系统内部错误）。

**Q4：怎么测越权？**
用低权限账号登录拿 token，去请求高权限接口，看是否被拦截。本项目实测：mall123 访问订单/会员返回 506 无操作权限，访问品牌返回 0（它确实有权限）——**正反两个方向都要验**。

**Q5：接口测试和界面测试的关系？**
互补。界面测的是"用户能不能用"，接口测的是"后端逻辑对不对"。同一个 Bug 在两条路径都复现，说明是后端问题；只有界面复现，可能是前端校验缺失。
